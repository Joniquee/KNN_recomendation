# Music Recommendation Service

Сервис рекомендаций музыки, который по текущему треку подбирает похожий — по аудио-характеристикам, а не по тегам или ручной разметке. Упрощённый аналог механики «следующий трек» в Spotify / Яндекс Музыке.

Ключевые алгоритмы (**PCA** и **KNN**) реализованы с нуля на NumPy, без `scikit-learn` — чтобы показать понимание математики под капотом, а не только умение вызвать `.fit()`.

## Демо

> Пользователь слушает трек → нажимает «Далее» → сервис подбирает похожий по звучанию трек.

---

## Зачем это бизнесу

Рекомендательные системы — прямой драйвер метрик в любом музыкальном сервисе: они увеличивают время прослушивания, удержание (retention) и вовлечённость. Подбор «по звучанию» особенно ценен для новых и нишевых треков, у которых ещё нет статистики прослушиваний (проблема «холодного старта»), — их невозможно рекомендовать классической коллаборативной фильтрацией, но можно по аудио-фичам.

---

## Возможности

- Рекомендация похожего трека по аудио-характеристикам текущего
- Снижение размерности признаков через PCA (собственная реализация)
- Поиск ближайших соседей через KNN по евклидовой метрике (собственная реализация)
- REST API на FastAPI для интеграции с любым фронтендом
- Веб-плеер на Streamlit с очередью треков и встроенным аудиоплеером

## Как это работает

Пайплайн рекомендации:

```
Аудио-фичи трека  ──►  PCA (снижение размерности)  ──►  KNN (поиск k ближайших)  ──►  Рекомендация
```

1. **Извлечение признаков.** Для каждого трека берутся аудио-характеристики из датасета FMA (`features.py`, `features_initiation.py`).
2. **PCA.** Признаковое пространство сжимается до 300 компонент, чтобы убрать шум и ускорить поиск (`PCA.py`), при этом сохраняя 88% информации.
3. **KNN.** В сжатом пространстве ищутся k ближайших треков по евклидову расстоянию (`KNN.py`).
4. **API.** FastAPI отдаёт метаданные, аудио и рекомендации (`main.py`).

### Датасет

Проект использует **[FMA: Free Music Archive](https://github.com/mdeff/fma)** (подмножество `fma_small`: 8 000 треков, 30 сек каждый).

Для запуска нужно скачать:
- `fma_small.zip` — аудиофайлы
- `fma_metadata.zip` — метаданные и признаки

Распаковать в папку `./data/`.

## Деплой

Docker Compose настроен для запуска обоих сервисов — бэкенда (FastAPI) и фронтенда (Streamlit) — в отдельных образах. Однако полноценный деплой через Docker ограничен из-за объёма датасета FMA: передача нескольких гигабайт аудиофайлов и фич внутрь контейнеров существенно усложняет процесс, поэтому в текущей конфигурации данные монтируются как volume с хост-машины.

**Текущая схема:**
- Бэкенд — Docker (локально).
- Фронтенд — Streamlit (локально).

## Запуск

### Предварительно

- Docker и Docker Compose
- Скачанный и распакованный датасет FMA в папку `./data/`
- Файл `.env` (см. `.env.example`)

### `.env`

```env
TRACKS_PATH=/app/data/fma_small/fma_small
API_URL=https://<ваш-streamlit-url>.streamlit.app
BACKEND_URL=http://localhost:8000
DEFAULT_TRACK_ID=051006
RAW_TRACKS=/app/data/fma_metadata/fma_metadata/raw_tracks.csv
FEATURES_CSV=/app/data/fma_metadata/fma_metadata/features.csv
```

### Запуск бэкенда и фронтэнда

```bash
docker compose up --build
```

API будет доступно на `http://localhost:8000`, интерактивная документация — на `http://localhost:8000/docs`.

## API

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `GET` | `/track_info/{track_id}` | Метаданные трека: название, исполнитель, обложка |
| `GET` | `/audio/{track_id}` | Аудиофайл трека (mp3) |
| `GET` | `/next_track?curent_track_id={id}` | Рекомендация следующего трека по текущему |

**Пример ответа** `/next_track`:

```json
{ "106236": "https://freemusicarchive.org/music/..." }
```

## Что можно улучшить (roadmap)

- [ ] **Масштабируемый поиск.** Сейчас KNN делает линейный перебор всех треков — O(n) на запрос. В проде стоит использовать FAISS / Annoy / HNSW.
- [ ] **Тесты.** Unit-тесты для KNN и PCA (pytest) + CI на GitHub Actions.
- [ ] **Метрики качества.** Офлайн-оценка релевантности рекомендаций.
- [ ] **Кэширование.** Предрассчитывать PCA-проекции и сохранять на диск, а не пересчитывать при каждом старте.
- [ ] **Облачный деплой бэкенда.** Вынести бэкенд на Railway / Render с подключением облачного хранилища для датасета.
